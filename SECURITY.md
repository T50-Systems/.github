# Security Policy

Security issues should be reported privately. Do not open a public issue with exploit details, credentials, customer data, or sensitive operational information.

## Reporting a vulnerability

Use the affected repository's **Security** tab and choose **Report a vulnerability** when available.

If private vulnerability reporting is not available for that repository, open a minimal public issue asking maintainers for a private security contact, but do not include sensitive details. A maintainer will provide a private channel.

Please include, when safe to share privately:

- affected repository, package, version, commit, or deployment;
- a concise description of the vulnerability;
- reproduction steps or proof of concept;
- expected impact and affected configurations;
- any suggested mitigation or patch.

## Response expectations

Maintainers will acknowledge reports as soon as practical, triage severity, and coordinate remediation. Timelines vary by project, impact, and maintainer availability.

## Coordinated disclosure

Please give maintainers a reasonable opportunity to investigate and release a fix before public disclosure. We will credit reporters when appropriate and requested.

## Supported versions

Unless a repository states otherwise, security fixes target the default branch and the latest released version. Older versions may receive fixes at maintainer discretion.
